# 任务工作报告

报告回答两个问题：做了什么；还需要用户审核、确认什么。根据实际文件、执行结果和验证证据写，不复述行动计划。

## 何时使用

用户明确要求，或任务包含多项成果、多个阶段、重要限制或需要用户决定的事项，简短聊天回复不足以交代时使用。一次小修改、简单回答、单纯生成索引通常不另建报告。任务量决定是否需要报告，是否有索引与此无关。

## 写法

默认保存 `任务报告.md`，标题用具体任务名称，正文仅两部分：

- **已完成**：按结果合并相关动作，给出有用的成果链接；必要的验证结果跟在对应成果后。只写实际完成的工作，部分完成要说清边界。
- **需要你审核、确认**：每项写清要看什么或决定什么，附对应入口与影响。没有事项时只写“暂无需要你确认的事项。” 未完成但助手仍能继续做的工作不转嫁给用户。

语言简洁、明确。一个事实只出现一次；概述、清单、验证、结尾之间不能换句话重复同一意思。没有必要时不加背景、过程流水账、统计、术语解释、结尾总结。保留影响使用或决策的限制，省略例行命令和内部临时文件。不要为凑出第二部分而索要没有必要的确认。

旧报告更新时保留未解决的决策项；已解决的移出待确认部分。用户说明、课程内容、下载清单、逐文件来源映射及机器校验日志不是本报告正文，保留在各自材料或工作记录中，不能为缩短报告而删除唯一记录。

## 后续更新：沿用还是新建

同一任务的修改、补充测试和审核反馈，默认更新原有报告及其 HTML 预览，沿用文件名与入口。将全文整理为当前状态：合并新增成果，替换已过时的结论，保留尚未解决的确认项，移除已经解决的待办。不要每轮另建“更新报告”，也不要在末尾不断追加重复流水账。

只有独立任务、用户明确要求分阶段留档，或某一版已作为正式提交/审计依据必须保留时，才新建带任务名称或日期的报告；必要时将旧版留在归档区，当前索引清楚区分当前版与历史版。不得覆盖用户撰写的课程报告、论文正文或唯一证据。需要详细过程时单独保留工作记录，不把历史叠加到简洁报告正文。

## 与文件索引的关系

本技能负责写报告，不生成索引，也不要求存在 HTML。报告可独立交付 Markdown 或直接在对话中按上述两部分汇报。

若用户同时需要索引，报告先作为普通文件保存；`maintain-html-index` 扫描到它后生成 HTML 预览并列入目录。索引不决定是否写报告，不替本技能补写结论，报告也不强制调用索引。独立 HTML 需求可交给通用渲染工具，不改变两部分内容。

## 交付前

核对完成项有证据、链接指向真实成果、待确认项有明确动作。通读整篇，合并语义重复；区分静态检查、实际打开和内容准确性。只交付必要入口，不在聊天中再次完整抄写报告。
