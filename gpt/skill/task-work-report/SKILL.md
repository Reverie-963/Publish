# 任务报告

像维护项目 README 一样，让用户快速了解当前结果、使用入口和影响决策的信息。结构服从内容，不固定为“已完成／待确认”两部分，也不照搬执行过程。

## 使用与组织

报告使用中文撰写，标题、说明和待确认事项均用中文；保留必要的文件名、代码标识及专有名词。除非用户明确要求其他语言，不生成英文版或中英双语报告，也不额外附英文摘要。

用户要求报告，或多项成果、重要限制等无法在简短回复中交代清楚时使用；一次小修改或单纯生成索引不必另建报告。

默认沿用 `任务报告.md`，标题写具体任务。通常先给结论或最有用的入口，再按需要补充使用方法、关键变化、验证依据或限制；没有内容的栏目直接省略。若有必须由用户决定的事项，按下面规则放在标题之后、其余正文之前。

写清结果及证据边界，避免把模拟检查说成实际打开、把局部验证说成完整验证。链接指向真实成果；例行命令、临时文件及过程流水账不进入报告。

## 不重复

同一个意思只保留在最合适的一处。概述不提前复述后文清单，验证结果跟对应结论写，末尾不再总结全文。更新时合并或替换原有段落，不将旧结论换个说法再追加。使用短句和必要的小标题；能删而不损失使用、判断所需信息的内容就删。

## 待确认事项置顶

用户要求之外、尚未获授权的额外操作，以及经核实仍无法确定且会影响用户选择的事项，集中放在最顶部的 **需要你确认** 提示中。每项只说明具体决定、必要影响和建议选择，并链接对应材料；正文不再复述。可自行核实的事实先核实，不把助手能继续完成的工作转交用户，也不重复请求已有授权。

- Markdown：使用 `> [!IMPORTANT]` 提示块，首段加粗“需要你确认”；标题层级与排版保证无颜色时仍能一眼看到。
- HTML：使用明显高于正文的加粗标题、高对比度深红色强调与浅红底色或左边线，深色模式也要清楚。保留文字标识，不只依赖颜色，不使用闪烁或整页警告效果。经索引生成的预览须保留提示样式，不能退化成普通引用。
- 多个独立决定或逐项审阅确有帮助时，使用未勾选的 `- [ ]` 清单；HTML 中需要勾选时使用有文字标签的复选框。互斥方案写成明确的单项选择，不用多个复选框表示。
- 勾选只记录用户的审阅选择，不自动执行额外操作。若勾选状态没有持久保存或没有写回原文，明确其作用范围，不声称已保存或已获得可执行授权。拟额外操作应写明尚未执行。

没有待确认事项就不显示提示块，也不写“暂无需要确认的事项”来凑栏目。

## 更新原文还是新建

同一任务默认维护一份当前报告：更新相关内容、删除过时表述，保留尚未解决的决定；已解决的确认项移出顶部，仅在其结果仍影响使用时融入正文。沿用文件名与入口，不每轮新建报告，不不断追加更新记录。

独立任务、用户明确要求分阶段留档，或某版已作为正式提交、审核依据必须保留时，另建带具体任务名或日期的报告。当前版与历史版明确区分，不覆盖用户的课程报告、论文或唯一证据。详细日志与来源映射保留在工作记录中，报告精简不能删除唯一记录。

## 与索引及交付的关系

本技能只负责报告内容与重点表达，可独立交付 Markdown、HTML 或对话文本，不自动生成索引。用户需要导航时，由 `maintain-html-index` 为已存在的报告制作预览并纳入目录；索引不决定是否需要报告。

交付前通读去重，核对入口、证据与顶部决定项。聊天中给必要入口和真正需要用户回应的决定，不再完整抄写报告。
