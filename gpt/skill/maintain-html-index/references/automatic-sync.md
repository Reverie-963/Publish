# 本机自动同步

默认在选定目录运行 `scripts/start_editor.py ROOT`。首次生成缺失的索引，再启动或复用带同步功能的本机入口；没有编辑需求的用户也可使用同一入口查看自动更新的预览。服务只监听本机，不上传文件。

- 每约 2 秒查看文件状态，变化稳定约 2 秒后更新索引和受影响预览；转换耗时另计。覆盖新增、修改、重命名、删除和空文件夹变化；连续保存合并处理。
- 沿用清单 `build_options` 中的入口名、标题、排除项、外部链接及预览限制。旧清单缺失配置时，先按原有选项重新生成，不能猜测排除范围后直接同步。
- 正文依赖的 `assets`、`source_assets` 等资源变化也触发重新生成。隐藏目录、`.file-index` 中的生成物/备份/运行文件和 Office 临时锁文件不会触发循环更新。用户明确排除的目录保持排除。
- 已删除或移动的文件从索引移除，并清理上一份清单明确拥有的旧预览目录；不会删除源文件或编辑备份。服务中继续访问旧预览会显示文件已移除，避免展示旧缓存。
- 本机入口中的页面在更新成功后自动刷新，并恢复滚动位置。正在编辑、保存、发生保存错误、选中文字或播放音视频时延后刷新。输入保留和源文件冲突保护优先于刷新；转换失败保留已有结果并重试，不声称失败文件已同步。
- 服务运行期间持续同步，不需要对话保持打开；电脑关机或服务停止后暂停。再次运行启动脚本即可恢复，并检查停止期间的文件变化。不会自动安装开机启动项。
- `file://` 离线页面不自行监听目录；服务可更新磁盘上的离线 HTML，但已经打开的离线标签页需要手动刷新。自动刷新和直接写回使用本机服务链接。
- 升级旧服务时创建新入口，保留旧会话，避免打断未保存输入；交付新链接并说明需要切换过去。不要突然终止用户正在使用的旧编辑会话。

实现：`scripts/watch_folder.py` 合并变动并调用增量生成器，`serve_editor.py` 更新文件映射并提供同步状态，`assets/auto-sync.js` 负责安全刷新。同步脚本仅由服务注入，不写入可离线移动的文件索引。

验证：`tests/check_sync.py` 在临时文件夹执行真实增删改名和 HTTP 检查；`tests/check_auto_sync.cjs` 检查刷新保护及状态恢复。DOM 模拟不代替浏览器视觉验证。
