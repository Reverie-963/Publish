# 已有资料改名与链接维护

在补拉或按网页顺序整理现有课程时使用。单纯下载到空文件夹不需要这套完整流程。

## 改名前

1. 按当前网页顺序建立“活动 → 本地原件/链接/译稿/答案”关系。以活动 URL/ID 作为识别线索，序号只是显示顺序，不能当成永久身份。
2. 记录所有计划移动的旧路径和最终新路径，包括受父目录改名影响的子文件。保留一份映射与 HTML/Markdown 内容快照到课程之外的临时目录。
3. 检查目标重名、大小写冲突、Unicode 规范化、非法字符、编号位数、路径长度；不覆盖现有文件。macOS 的冒号在 Finder 中可能显示成斜杠，文件操作以真实路径为准。
4. 同目录的 `.original.md`、`.zh.md` 与原件编号/标题同步，`assets/<原文stem>/` 保持来源分组，图片内部文件名不必改。遗留 `_翻译` 目录按本次授权范围迁移为同目录文稿并修复引用；尚未迁移的旧目录及 `_双语作业` 目录仍需保持对应。已填写版本保留“已填写/作者”等后缀。
5. 区分旧资料版本和字节完全相同的冗余副本。即使内容相同，不同网页条目的入口关系仍需在目录中保留。

## 执行移动

嵌套移动有实际顺序风险：仅按旧路径深度从深到浅操作并不充分。来自板块根目录的文件若要移入一个同时被改名的课程子目录，可能在父目录改名后重新创建旧目录，造成分裂。

选择适合实际变更的一种策略：

- 先把所有跨目录条目移到目标父目录的**现有位置**，完成内部文件改名，再从内到外重命名父目录；必须显式计算依赖顺序。
- 或在同一文件系统内使用唯一的临时暂存目录分阶段搬移。先快照内容与路径，把待变更条目安全暂存，再建立最终目录结构并恢复文件；检查覆盖条件，保留回滚映射。父子条目不能重复搬移同一份数据。

路径操作使用支持 Unicode 的文件 API，不用按空格拆分命令输出。每次失败后先查看实际文件状态和已完成映射，再继续剩余操作；不要盲目重新运行整个批次。

## 更新链接

- 对每篇 Markdown，分别知道它的**旧位置**与**新位置**。先把原本的相对链接解析到旧绝对目标，再经映射得到新目标，最后计算从新文稿位置出发的相对路径。
- 同时处理 HTML 导航的 href/src、报告、目录索引、原文/译文互链、源文件链接、图片链接、带空格的 `<...>` 链接和百分号编码路径；保留查询/片段部分。
- 不对全文做不区分上下文的 basename 替换。同一个旧文件名可能在不同板块存在，正文中的普通词也可能与文件名相同。
- 用户写作内容不为整理而改写。只更新能确认是路径/文件名的引用、受影响的保存位置说明，以及本次生成的资料目录。
- 断点恢复时，先判断链接是否已经指向有效的新路径；尚未更新的链接再按旧路径映射。防止二次添加编号。
- 仅调整编号或名称时，不更改 `.webloc` 中的 Moodle 目标 URL，只改本地文件名。增量更新发现入口确实变化时，按 [增量更新与续传](incremental-update.md) 核实后同步目标 URL 与目录来源链接。

## 完成检查

改名后从变更的 MD 重新生成对应 HTML 阅读版，报告同步生成 HTML；目录锚点及网页互链继续有效。所有计划的新路径都存在；没有意外重建的旧父目录；每个板块中课程条目的编号与网页顺序一致；源文件及正式译稿/答案没有丢失；HTML 导航与 Markdown 的本地链接仍可解析。不要为了检查改名而重复下载整门课程或重新转换已验证的文档。

更改记录可以留在临时工作区或与废纸篓中的恢复材料放在一起，不作为用户需要浏览的课程附件。
