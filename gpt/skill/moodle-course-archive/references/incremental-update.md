# 增量更新与续传

目标：同一课程重复运行时复用已有可用资料，只补缺失内容；网页新增、解锁、改名或重排后，本地编号、入口、目录和引用保持对应。此流程按用户请求执行，不自行创建定时任务。

## 1. 识别条目，建立当前对应关系

- 先读本地 HTML 导航、来源与状态记录、来源链接和 `.webloc`，再读取当前课程页面。使用“站点 + 课程 ID/学年 + 活动类型及 ID”识别活动；编号与标题是可变属性，不是身份。跨站点、跨课程的同名项目不能合并。
- Moodle 文件夹内逐项匹配，以父活动及页面实际提供的文件标识或相对路径为依据。查询串中的临时令牌或修订参数变化本身不证明新增文件；结合标题、格式、已知来源和可见版本信息判断。
- 旧归档没有活动映射时，从已有入口、文稿来源、去掉编号后的名称和文件内容建立对应关系。标题相同但来源不清时继续核对，不立即重新下载，也不凭同名认定是同一项。仍无法确定的保留原件并标为待确认。
- 在 已有来源记录 中保留“网页条目（稳定来源链接/活动 ID）—本地文件—状态”对应关系；实际 HTML 索引入口 仅按层级列出名称和链接，同一活动的原件/译稿/入口放在同一节点。直接更新现有导航和来源与状态记录，不另建重复索引。正文 MD 或来源与状态记录有变化时同步重建对应 HTML 阅读版（含目录），导航指向 HTML；保留 MD 供本地查看。没有机器清单或旧清单被删除不影响增量更新。
- 完整展开当前范围内的板块、文件夹及限制提示；先排除页面未加载完、会话失效等情况，再判断条目消失。临时差异清单、恢复映射和检查记录置于课程目录之外，不保存登录凭证。

## 2. 按差异执行

| 当前情况 | 操作 |
|---|---|
| 对应的本地原件/网页 PDF/正文 MD 可用 | 复用，不传输正文；仅更新有变化的名称、编号、来源或目录 |
| 新增活动，或既有文件夹新增附件 | 只保存尚缺的内容，按当前网页位置纳入编号 |
| 原先锁定，仅有入口，现在已解锁 | 通过正常入口补下载缺失正文；保留有用入口，共用编号，清除过期锁定提示 |
| Quiz、作业提交等交互项解锁 | 更新入口及状态，不开始、作答或提交 |
| 仍锁定或访问失败 | 复用入口，更新实际前置条件或访问原因，不生成重复占位文件 |
| 原下载不完整、零字节、损坏或实际为错误页 | 重新取得缺失的有效副本；不要把用户编辑稿误判为损坏原件 |
| 只有标题、网页顺序或板块位置变化 | 保留文件内容，改名/移动并更新引用，不重新下载 |
| 同一活动有明确的新版本证据，但本地已有有效旧版 | 默认只补缺，不覆盖或重复下载；在来源与状态记录中记录已观察到的版本变化。用户明确要求更新版本时才取得新版，保留用户编辑稿，标明依赖旧版的译稿未同步更新 |
| 当前网页不再列出本地条目 | 先确认页面完整；保留本地资料并在来源与状态记录中标为“网页当前未列出”，在导航保留其可访问链接，不计入当前活动编号序列，不自动删除。若旧编号冲突，用安全改名流程去掉历史项的活动序号并维护引用 |

访问页面以识别状态或链接可以正常进行；不要为比较字节而再次下载已有完整附件，不把自动触发的下载当作必需检查。网页正文已有离线副本时，默认补缺模式也不重复导出 PDF。

## 3. 同步编号与链接

1. 计算整个受影响板块的最终顺序；中间插入新条目时，后续旧条目顺延。锁定项仍占位，同一条目的附件、快捷方式、译稿、答案及资源文件夹维持对应关系。
2. 先读 [已有资料改名与链接维护](existing-files.md)，建立旧路径到新路径映射，检查重名和父子目录移动依赖。使用安全暂存或明确的移动顺序，不覆盖目标文件。
3. 根据路径映射更新课程/板块 HTML 导航、来源与状态记录、Markdown 相对链接和图片引用。跨板块移动还要检查其他板块中指向该条目的引用；资源内部无关文件名不动。
4. 统一导航优先保留稳定的 Moodle 活动入口；既有 `.webloc` 沿用其入口信息，不要求新建快捷方式。仅编号或标题变化不改变目标 URL。若页面实际提供了变更后的有效入口，核实课程、标题及归属后更新快捷方式与目录中的来源链接；不根据编号推算或编造 URL。
5. 来源与状态记录中的锁定说明只保留仍未解决的条件，缺失说明只保留仍缺的项目。全部解决时清除已解决的状态并更新来源与状态记录的当前结论，不删除来源与状态记录中的其他记录；保留用户添加的文字。不要留下互相矛盾的新旧清单。

## 4. 续传与结果检查

- 每份新下载先暂存，检查实际格式和可读性后再放入最终位置；验证成功才记为已保存。失败时保留入口和原因，不把临时文件算作完成。
- 中断后读取实际磁盘状态重建差异，复用已完成的文件，只处理剩余下载和未完成改名。不盲目重跑旧移动指令，不因临时清单缺失重新下载全部资料。
- 对未变条目避免无意义地重写文件、日期和目录；无变化的再次运行应产生零新增正文下载、零重复文件、零无必要改名。
- 检查当前网页与编号一致、同条目多种形式共用编号、重命名没有覆盖文件、本地引用可达、解锁说明与实际状态一致。不得声称复用文件已与远端逐字节核验。
- 最后在已有来源记录中更新实际新增/解锁补齐数、复用数、改名情况及剩余障碍，需要时更新其阅读预览，技术日志/机器验证文件仍放在临时工作区。

应满足的典型结果：

- 网页无变化：零正文下载，已有路径和内容不变。
- A、C 之间新增 B：仅下载 B，C 及其译稿顺延，指向 C 的本地链接同步修改。
- 同一活动从锁定变为可用：已有入口旁只增加一份缺失原件，旧锁定提示消失；再次运行不重复下载。
- 文件夹已有三份附件，新增第四份：仅下载第四份，必要时调整内部编号。
- 用户删除旧校验 JSON：依靠资料目录、入口和文件继续匹配，不全量重下。
- 中断后已有部分新增资料保存成功：续传只补余下项目，安全完成尚未应用的改名和引用更新。
